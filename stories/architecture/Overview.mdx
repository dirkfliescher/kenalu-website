## Routing und Datenfetch

### Storyblok-Seiten
Die meisten Seiten fetchen ihren Content aus Storyblok:

```js
// Standard-Pattern: app/about/page.js
export const revalidate = 60; // ISR: neu laden nach 60s

const { data } = await Storyblok.get('cdn/stories/about', {
  version: process.env.NODE_ENV === 'development' ? 'draft' : 'published',
});

const body = data.story.content.body || [];
return body.map((blok) => <DynamicBlock key={blok._uid} blok={blok} />);
```

### Statische Seiten
Service-Detailseiten (`/services/klarheit` etc.) fetchen Storyblok **nur für SEO-Metadata**; der gesamte Seiten-Content ist hardcodiertes JSX.

---

## Deployment

- **Hosting:** Vercel (Auto-Deploy bei `git push origin main`)
- **Branch:** `main` → Production
- **ISR:** `revalidate = 60` auf allen Storyblok-Seiten (Content-Änderungen live nach max. 60s)

---

## Umgebungsvariablen

| Variable | Zweck |
|---|---|
| `STORYBLOK_TOKEN` | Content Delivery API (Preview Token) |
| `OPENAI_API_KEY` | Kai-Chat (gpt-4o-mini) |

Diese sind in `.env.local` (nicht im Repo) und in Vercel Environment Variables gesetzt.

> ⚠️ Der Storyblok Management API PAT (`STORYBLOK_PAT`) darf **nicht** ins Git-Repo.
